# 移行手順

[../../IAMIdentityCenter/sample/before/iam-groups.yaml](../../IAMIdentityCenter/sample/before/iam-groups.yaml) の構成（`DevelopersTestGroup` / `InfraTestGroup` が1つのアカウント内で直接ポリシーを持つ状態）から、開発・検証・商用の3アカウント構成 + スイッチロールへ移行する手順。

> 以下のアカウント ID はすべて説明用のダミー値。
> - ベースアカウント（現在 IAM グループがあるアカウント）: `111122223333`
> - 開発アカウント: `222233334444`
> - 検証アカウント: `333344445555`
> - 商用アカウント: `444455556666`

## 全体像

```
[ベースアカウント 111122223333]              [開発 222233334444] [検証 333344445555] [商用 444455556666]
  Developers グループ  ──AssumeRole──────────►  DevelopersRole  ──►  DevelopersRole   （✕ 通常は不可）
  Infra グループ       ──AssumeRole──────────►  InfraRole       ──►  InfraRole        （✕ 通常は不可）
  ProdOperators グループ ──AssumeRole───────────────────────────────────────────────►  DevelopersRole / InfraRole
```

- 現状は「グループ＝権限そのもの」だったが、移行後は「グループ＝どの環境ロールに切り替えられるかの権限」に役割が変わる
- 実際の権限（PowerUserAccess・カスタムポリシー）は各環境アカウント側のロールに移る

## フェーズ 0: アカウント準備

1. 開発・検証・商用の3つの AWS アカウントを用意する（Organizations 配下のメンバーアカウントでよい。Identity Center のような組織全体での有効化は不要）
2. 各アカウントの AWS アカウント ID を控える

## フェーズ 1: 各環境アカウントにロールを作成

[templates/target-account-roles.yaml](./templates/target-account-roles.yaml) を、**開発・検証・商用それぞれのアカウントに1回ずつ**デプロイする。

```bash
# 開発アカウント（222233334444）にログインした状態で実行
aws cloudformation deploy \
  --template-file templates/target-account-roles.yaml \
  --stack-name switch-role-roles \
  --parameter-overrides \
    EnvironmentName=Development \
    TrustedPrincipalArns=arn:aws:iam::111122223333:root \
    RequireMfa=false \
    MaxSessionDuration=28800 \
  --capabilities CAPABILITY_NAMED_IAM

aws cloudformation describe-stacks --stack-name switch-role-roles \
  --query "Stacks[0].Outputs"
# => DevelopersRoleArn, InfraRoleArn を控える
```

検証アカウント（333344445555）にも同様に `EnvironmentName=Staging` でデプロイする。

商用アカウント（444455556666）だけは `TrustedPrincipalArns` と `RequireMfa` の指定が異なる（[04-環境別アクセス制御.md](./04-環境別アクセス制御.md) 参照）。

```bash
# 商用アカウント（444455556666）にログインした状態で実行
aws cloudformation deploy \
  --template-file templates/target-account-roles.yaml \
  --stack-name switch-role-roles \
  --parameter-overrides \
    EnvironmentName=Production \
    TrustedPrincipalArns=arn:aws:iam::111122223333:user/taro.yamada,arn:aws:iam::111122223333:user/hanako.suzuki \
    RequireMfa=true \
    MaxSessionDuration=3600 \
  --capabilities CAPABILITY_NAMED_IAM
```

## フェーズ 2: ベースアカウント側を AssumeRole 許可ポリシーに置き換え

フェーズ1で取得した6つのロール ARN（開発・検証・商用 × Developers・Infra）を使って、[templates/base-account-assume-role-policies.yaml](./templates/base-account-assume-role-policies.yaml) をベースアカウントにデプロイする。

```bash
# ベースアカウント（111122223333）にログインした状態で実行
aws cloudformation deploy \
  --template-file templates/base-account-assume-role-policies.yaml \
  --stack-name switch-role-assume-policies \
  --parameter-overrides \
    DevDevelopersRoleArn=arn:aws:iam::222233334444:role/DevelopmentDevelopersRole \
    DevInfraRoleArn=arn:aws:iam::222233334444:role/DevelopmentInfraRole \
    StagingDevelopersRoleArn=arn:aws:iam::333344445555:role/StagingDevelopersRole \
    StagingInfraRoleArn=arn:aws:iam::333344445555:role/StagingInfraRole \
    ProdDevelopersRoleArn=arn:aws:iam::444455556666:role/ProductionDevelopersRole \
    ProdInfraRoleArn=arn:aws:iam::444455556666:role/ProductionInfraRole \
  --capabilities CAPABILITY_NAMED_IAM
```

これにより `Developers` / `Infra` / `ProdOperators` の3グループと、それぞれに紐づく AssumeRole 許可ポリシーが作成される。

## フェーズ 3: ユーザーをグループへ振り分け（CFN 管理外）

[../../IAMIdentityCenter/02-CloudFormation管理方針.md](../../IAMIdentityCenter/02-CloudFormation管理方針.md) と同じ考え方で、ユーザーのグループ所属は CloudFormation では管理しない。

```bash
# 通常メンバー: Developers または Infra グループへ
aws iam add-user-to-group --user-name taro.yamada --group-name Developers
aws iam add-user-to-group --user-name hanako.suzuki --group-name Infra

# 商用アクセスを許可する少数のメンバーのみ、追加で ProdOperators グループへ
aws iam add-user-to-group --user-name taro.yamada --group-name ProdOperators
aws iam add-user-to-group --user-name hanako.suzuki --group-name ProdOperators
```

## フェーズ 4: 動作確認

1. `taro.yamada` でベースアカウントにサインインし、開発アカウントの `DevelopmentDevelopersRole` へスイッチロールできること、`PowerUserAccess` 相当の操作ができることを確認する
2. 同様に検証アカウントへのスイッチロールを確認する
3. 商用アカウントへのスイッチロールを確認する。`ProdOperators` に入れていないユーザーでは切り替えできない（信頼ポリシーで拒否される）ことも合わせて確認する
4. MFA 未認証の状態で商用ロールへの切り替えを試み、拒否されることを確認する（[04-環境別アクセス制御.md](./04-環境別アクセス制御.md) 参照）

## フェーズ 5: 旧構成の削除

動作確認が完了したら、ベースアカウントに残っている旧 `DevelopersTestGroup` / `InfraTestGroup`（直接ポリシーがアタッチされたグループ）のスタックを削除する。

```bash
aws cloudformation delete-stack --stack-name iam-groups
```
