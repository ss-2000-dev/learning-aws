# 移行手順

[../../IAMIdentityCenter/sample/before/iam-groups.yaml](../../IAMIdentityCenter/sample/before/iam-groups.yaml) の構成（`DevelopersTestGroup` / `InfraTestGroup` が1つのアカウント内で直接ポリシーを持つ状態）から、**ベースアカウントが検証（Staging）環境を兼ねる**3アカウント構成 + スイッチロールへ移行する手順。

> 以下のアカウント ID はすべて説明用のダミー値。
> - ベースアカウント（検証環境を兼ねる。現在 IAM グループがあるアカウント）: `111122223333`
> - 開発アカウント: `222233334444`
> - 商用アカウント: `444455556666`

## 全体像

```
[ベースアカウント 111122223333 = 検証環境]        [開発 222233334444]        [商用 444455556666]
  DevelopersTestGroup（PowerUserAccess を直接保持。検証環境自体の権限）
    └─AssumeRole 許可を追加───────────────►  DevelopersRole              （✕ 通常は不可）
  InfraTestGroup（カスタムポリシーを直接保持。検証環境自体の権限）
    └─AssumeRole 許可を追加───────────────►  InfraRole                   （✕ 通常は不可）
  ProdOperators グループ（新設）
    └─AssumeRole 許可───────────────────────────────────────────────►  DevelopersRole / InfraRole
```

- 検証環境（ベースアカウント自身）へのアクセスは何も変わらない。既存グループが持つ直接ポリシー（`PowerUserAccess` 等）はそのまま使い続ける
- 開発・商用環境へのアクセスだけが新規追加。既存グループに「AssumeRole 許可」を追加でアタッチする
- 商用環境は既存グループとは別に新設する `ProdOperators` グループのみが AssumeRole 可能

## フェーズ 0: アカウント準備

1. 開発・商用の2つの AWS アカウントを新たに用意する（Organizations 配下のメンバーアカウントでよい。Identity Center のような組織全体での有効化は不要）
2. 各アカウントの AWS アカウント ID を控える
3. ベースアカウント（検証環境）は新規に用意する必要はない。現状のまま使う

## フェーズ 1: 開発・商用アカウントにロールを作成

[templates/target-account-roles.yaml](./templates/target-account-roles.yaml) を、**開発・商用それぞれのアカウントに1回ずつ**デプロイする（検証環境はベースアカウント自身なので、このテンプレートのデプロイは不要）。

```bash
# 開発アカウント（222233334444）にログインした状態で実行
aws cloudformation deploy \
  --template-file templates/target-account-roles.yaml \
  --stack-name switch-role-roles \
  --parameter-overrides \
    EnvironmentName=Development \
    TrustedPrincipalArns=arn:aws:iam::111122223333:root \
    RequireMfa=false \
    MaxSessionDuration=28800 \
  --capabilities CAPABILITY_NAMED_IAM

aws cloudformation describe-stacks --stack-name switch-role-roles \
  --query "Stacks[0].Outputs"
# => DevelopersRoleArn, InfraRoleArn を控える
```

商用アカウント（444455556666）は `TrustedPrincipalArns` と `RequireMfa` の指定が異なる（[04-環境別アクセス制御.md](./04-環境別アクセス制御.md) 参照）。

```bash
# 商用アカウント（444455556666）にログインした状態で実行
aws cloudformation deploy \
  --template-file templates/target-account-roles.yaml \
  --stack-name switch-role-roles \
  --parameter-overrides \
    EnvironmentName=Production \
    TrustedPrincipalArns=arn:aws:iam::111122223333:user/taro.yamada,arn:aws:iam::111122223333:user/hanako.suzuki \
    RequireMfa=true \
    MaxSessionDuration=3600 \
  --capabilities CAPABILITY_NAMED_IAM
```

### コンソールで操作する場合

対象アカウント（開発／商用）ごとに、以下を1回ずつ実施する。

1. 対象アカウントにサインインし、**CloudFormation コンソール**を開く
2. 「**スタックを作成**」→「**新しいリソースを使用（標準）**」を選択
3. 「テンプレートファイルのアップロード」を選び、[templates/target-account-roles.yaml](./templates/target-account-roles.yaml) を選択して「次へ」
4. スタック名を入力する（例: `switch-role-roles`）
5. パラメータを入力する
   - **EnvironmentName**: プルダウンから `Development` / `Production` を選択
   - **TrustedPrincipalArns**: 信頼する Principal の ARN をカンマ区切りで入力（開発は `arn:aws:iam::111122223333:root`、商用は許可する個別ユーザーの ARN）
   - **RequireMfa**: 商用のみ `true`、開発は `false`
   - **MaxSessionDuration**: 開発は `28800`、商用は `3600`
6. 「次へ」→スタックオプションはそのまま「次へ」
7. 確認画面の一番下にある「**AWS CloudFormation によって IAM リソースが作成される場合があることを承認します**」にチェックを入れ、「送信」
8. スタックのステータスが `CREATE_COMPLETE` になるまで待つ
9. スタックの「**出力**」タブを開き、`DevelopersRoleArn` / `InfraRoleArn` を控える（フェーズ2で使用）

## フェーズ 2: ベースアカウント（検証環境）の既存グループに AssumeRole 許可を追加

フェーズ1で取得した4つのロール ARN（開発・商用 × Developers・Infra）を使って、[templates/staging-account-assume-role-policies.yaml](./templates/staging-account-assume-role-policies.yaml) をベースアカウントにデプロイする。

**既存の `DevelopersTestGroup` / `InfraTestGroup` は削除・再作成しない。** このテンプレートは、既存グループの名前を指定してポリシーを追加アタッチするだけで、グループ自体は触らない。

```bash
# ベースアカウント（111122223333）にログインした状態で実行
aws cloudformation deploy \
  --template-file templates/staging-account-assume-role-policies.yaml \
  --stack-name switch-role-assume-policies \
  --parameter-overrides \
    ExistingDevelopersGroupName=DevelopersTestGroup \
    ExistingInfraGroupName=InfraTestGroup \
    DevDevelopersRoleArn=arn:aws:iam::222233334444:role/DevelopmentDevelopersRole \
    DevInfraRoleArn=arn:aws:iam::222233334444:role/DevelopmentInfraRole \
    ProdDevelopersRoleArn=arn:aws:iam::444455556666:role/ProductionDevelopersRole \
    ProdInfraRoleArn=arn:aws:iam::444455556666:role/ProductionInfraRole \
  --capabilities CAPABILITY_NAMED_IAM
```

これにより、既存の `DevelopersTestGroup` / `InfraTestGroup` に開発アカウントへの AssumeRole 許可が追加され、さらに商用専用の新規グループ `ProdOperators` とその AssumeRole 許可ポリシーが作成される。

### コンソールで操作する場合

1. ベースアカウントにサインインし、**CloudFormation コンソール**を開く
2. 「**スタックを作成**」→「**新しいリソースを使用（標準）**」を選択
3. 「テンプレートファイルのアップロード」を選び、[templates/staging-account-assume-role-policies.yaml](./templates/staging-account-assume-role-policies.yaml) を選択して「次へ」
4. スタック名を入力する（例: `switch-role-assume-policies`）
5. パラメータを入力する
   - **ExistingDevelopersGroupName** / **ExistingInfraGroupName**: 既存のグループ名（デフォルト値のままでよければ入力不要）
   - フェーズ1の「出力」タブで控えた4つのロール ARN（開発・商用 × Developers・Infra）
6. 「次へ」→スタックオプションはそのまま「次へ」
7. 確認画面で「**AWS CloudFormation によって IAM リソースが作成される場合があることを承認します**」にチェックを入れ、「送信」
8. スタックのステータスが `CREATE_COMPLETE` になるまで待つ

## フェーズ 1・2 の代替: 統合テンプレート（switch-role-all-in-one.yaml）を使う場合

フェーズ1・フェーズ2で使った2つのテンプレートは、[templates/switch-role-all-in-one.yaml](./templates/switch-role-all-in-one.yaml) 1つにまとめられている。`DeploymentTarget` パラメータと `Condition` で、デプロイ先に応じて作成するリソースが自動的に切り替わる仕組み。テンプレートを分けたくない場合はこちらを使う（結果はフェーズ1・2を個別に実施した場合と同じ）。

同じ1ファイルを、**開発・商用・ベースアカウントの3つのアカウントにそれぞれ1回ずつ**、`DeploymentTarget` の値だけ変えてデプロイする。

```bash
# 開発アカウント（222233334444）にログインした状態で実行
aws cloudformation deploy \
  --template-file templates/switch-role-all-in-one.yaml \
  --stack-name switch-role \
  --parameter-overrides \
    DeploymentTarget=Development \
    TrustedPrincipalArns=arn:aws:iam::111122223333:root \
    RequireMfa=false \
    MaxSessionDuration=28800 \
  --capabilities CAPABILITY_NAMED_IAM

aws cloudformation describe-stacks --stack-name switch-role \
  --query "Stacks[0].Outputs"
# => DevelopersRoleArn, InfraRoleArn を控える
```

```bash
# 商用アカウント（444455556666）にログインした状態で実行
aws cloudformation deploy \
  --template-file templates/switch-role-all-in-one.yaml \
  --stack-name switch-role \
  --parameter-overrides \
    DeploymentTarget=Production \
    TrustedPrincipalArns=arn:aws:iam::111122223333:user/taro.yamada,arn:aws:iam::111122223333:user/hanako.suzuki \
    RequireMfa=true \
    MaxSessionDuration=3600 \
  --capabilities CAPABILITY_NAMED_IAM

aws cloudformation describe-stacks --stack-name switch-role \
  --query "Stacks[0].Outputs"
# => DevelopersRoleArn, InfraRoleArn を控える
```

```bash
# ベースアカウント（111122223333）にログインした状態で実行
# 開発・商用アカウントの Outputs で取得した4つの ARN を使う
aws cloudformation deploy \
  --template-file templates/switch-role-all-in-one.yaml \
  --stack-name switch-role \
  --parameter-overrides \
    DeploymentTarget=Staging \
    ExistingDevelopersGroupName=DevelopersTestGroup \
    ExistingInfraGroupName=InfraTestGroup \
    DevDevelopersRoleArn=arn:aws:iam::222233334444:role/DevelopmentDevelopersRole \
    DevInfraRoleArn=arn:aws:iam::222233334444:role/DevelopmentInfraRole \
    ProdDevelopersRoleArn=arn:aws:iam::444455556666:role/ProductionDevelopersRole \
    ProdInfraRoleArn=arn:aws:iam::444455556666:role/ProductionInfraRole \
  --capabilities CAPABILITY_NAMED_IAM
```

### コンソールで操作する場合

3つのアカウントそれぞれで、以下を1回ずつ実施する。アップロードするテンプレートファイルは常に同じ `switch-role-all-in-one.yaml` で、パラメータだけがアカウントごとに異なる。

1. 対象アカウントにサインインし、**CloudFormation コンソール**を開く
2. 「**スタックを作成**」→「**新しいリソースを使用（標準）**」を選択
3. 「テンプレートファイルのアップロード」を選び、[templates/switch-role-all-in-one.yaml](./templates/switch-role-all-in-one.yaml) を選択して「次へ」
4. スタック名を入力する（例: `switch-role`）
5. **DeploymentTarget** をまず選択し、それに応じて以下のパラメータを入力する（使わない側のパラメータは未入力のままでよい。Default が入る）
   - `Development` / `Production` を選んだ場合: `TrustedPrincipalArns`・`RequireMfa`・`MaxSessionDuration`
   - `Staging` を選んだ場合: `ExistingDevelopersGroupName`・`ExistingInfraGroupName`・開発/商用アカウントの4つのロール ARN
6. 「次へ」→スタックオプションはそのまま「次へ」
7. 確認画面の一番下にある「**AWS CloudFormation によって IAM リソースが作成される場合があることを承認します**」にチェックを入れ、「送信」
8. スタックのステータスが `CREATE_COMPLETE` になるまで待つ
9. `Development` / `Production` でデプロイした場合は「**出力**」タブから `DevelopersRoleArn` / `InfraRoleArn` を控える（`Staging` デプロイ時に必要）

## フェーズ 3: 商用アクセスを許可するユーザーだけを ProdOperators グループへ（CFN 管理外）

[../../IAMIdentityCenter/02-CloudFormation管理方針.md](../../IAMIdentityCenter/02-CloudFormation管理方針.md) と同じ考え方で、ユーザーのグループ所属は CloudFormation では管理しない。

**既存の `DevelopersTestGroup` / `InfraTestGroup` のメンバーは何も変更不要。** 元々そのグループに入っているユーザーが、そのまま開発アカウントへも切り替えられるようになる。作業が必要なのは商用アクセスを許可する少数のユーザーだけ。

```bash
# 商用アクセスを許可する少数のメンバーのみ、追加で ProdOperators グループへ
aws iam add-user-to-group --user-name taro.yamada --group-name ProdOperators
aws iam add-user-to-group --user-name hanako.suzuki --group-name ProdOperators
```

### コンソールで操作する場合

1. **IAM コンソール**を開く
2. 左メニューの「**ユーザーグループ**」から `ProdOperators` を選択
3. 「**ユーザーを追加**」ボタンをクリック
4. 商用アクセスを許可したいユーザーにチェックを入れ、「**ユーザーの追加**」で確定

   （ユーザー側の画面から操作する場合は、「ユーザー」→対象ユーザーを選択→「グループ」タブ→「グループの追加」でも同じ結果になる）

## フェーズ 4: 動作確認

1. `taro.yamada` でベースアカウントにサインインし、**検証環境（ベースアカウント自身）では今まで通り直接権限で操作できる**ことを確認する（スイッチロール不要・変化なし）
2. 開発アカウントの `DevelopmentDevelopersRole` へスイッチロールできること、`PowerUserAccess` 相当の操作ができることを確認する
3. 商用アカウントへのスイッチロールを確認する。`ProdOperators` に入れていないユーザーでは切り替えできない（信頼ポリシーで拒否される）ことも合わせて確認する
4. MFA 未認証の状態で商用ロールへの切り替えを試み、拒否されることを確認する（[04-環境別アクセス制御.md](./04-環境別アクセス制御.md) 参照）

### コンソールでのスイッチロール操作手順

1. ベースアカウントにコンソールでサインインする
2. 画面右上の**アカウント名（ユーザー名）のメニュー**をクリックし、「**ロールの切り替え**」を選択
3. 以下を入力する
   - **アカウント**: 切り替え先の AWS アカウント ID（例: 開発アカウント `222233334444`）
   - **ロール**: ロール名（例: `DevelopmentDevelopersRole`）
   - **表示名**（任意）: 画面右上に表示するニックネーム（例: `Dev-Developers`）
4. 「**ロールの切り替え**」ボタンをクリック
5. 画面右上の表示が指定したロール名（表示名）に変わっていれば切り替え成功。権限がない、または信頼ポリシーで許可されていない場合はエラーメッセージが表示され切り替えられない
6. 元のユーザーに戻るには、右上メニューから「**元のユーザーに戻る**」を選択する

商用ロールで MFA 未認証時に拒否されることを確認する場合は、ベースアカウントに MFA 認証**せずに**サインインした状態（または MFA デバイスを一時的に外したテスト用ブラウザプロファイル等）で同様の手順を行い、「ロールの切り替え」がエラーになることを確認する。

## フェーズ 5: 完了

**削除する既存リソースはない。** ベースアカウントの `DevelopersTestGroup` / `InfraTestGroup` とその直接ポリシーは、検証環境の権限としてそのまま稼働し続ける。今回追加したのは AssumeRole 許可ポリシー（フェーズ2）と `ProdOperators` グループのみで、これらも削除しない。
