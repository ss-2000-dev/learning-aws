# セッション時間

スイッチロールのセッション時間はどこまで短縮できるか、という質問への回答。

## 結論

| 利用方法 | 短縮できる下限 |
|---|---|
| **マネジメントコンソールの「ロールの切り替え」** | **1時間（60分）**。これより短くはできない |
| **CLI / SDK で `sts:AssumeRole` を直接呼ぶ** | **15分（900秒）** まで短縮可能 |

IAM Identity Center のユーザーインタラクティブセッション（[../../IAMIdentityCenter/05-セッション設定.md](../../IAMIdentityCenter/05-セッション設定.md)、15分まで短縮可）と比べると、**コンソールでのスイッチロールは 1時間が下限**という点で見劣りする。これはスイッチロールが依拠している IAM ロールの `MaxSessionDuration` という設定項目自体に、AWS 側で決められた下限があるため。

## 仕組みの詳細

### IAM ロールの `MaxSessionDuration`

IAM ロールには「このロールを引き受けたセッションを最大何秒間有効にするか」を決める `MaxSessionDuration` というプロパティがある。

- 設定可能な範囲: **3,600秒（1時間）〜43,200秒（12時間）**
- **1時間より短く設定することはできない**（AWS のハード制約）
- 未設定の場合のデフォルトは 1時間

### コンソールで「ロールの切り替え」をした場合

コンソールの「ロールの切り替え」機能には、ユーザーがセッション時間を選ぶ UI が無い。付与されるセッション時間は次のいずれか短い方になる。

- ロールの `MaxSessionDuration`
- 切り替え元のユーザー自身のセッションの残り時間

`MaxSessionDuration` の下限が 1時間である以上、**コンソール経由のスイッチロールは 1時間より短くならない**。

### CLI / SDK で `sts:AssumeRole` を直接呼ぶ場合

`aws sts assume-role` コマンドや SDK から直接 `AssumeRole` を呼ぶ場合は、`DurationSeconds` パラメータでセッション時間を明示的に指定できる。

- 指定可能な範囲: **900秒（15分）〜 ロールの `MaxSessionDuration`**
- ロールの `MaxSessionDuration` が 3,600秒（デフォルト）のままでも、`DurationSeconds=900` を指定すれば 15分のセッションを発行できる

```bash
aws sts assume-role \
  --role-arn arn:aws:iam::444455556666:role/ProdDevelopersRole \
  --role-session-name taro-yamada-prod \
  --duration-seconds 900
```

ただし、これは CLI や自動化スクリプトから直接呼ぶ場合の話であり、**マネジメントコンソールを使う一般的な運用ではこのオプションは使えない**。

### ロールチェイニングの注意点

すでに一時的な認証情報（あるロールを引き受けた状態）を使って、さらに別のロールへスイッチロールする場合（ロールチェイニング）は、`MaxSessionDuration` の設定に関わらず**最大1時間に制限される**。多段階でロールを切り替える構成をとる場合は注意する。

## 推奨設定

- 開発環境: 業務の利便性を優先し `MaxSessionDuration` は 8時間（`28800`）程度でよい（検証環境はベースアカウント自身のため、そもそもこの設定の対象外）
- 商用環境: プラットフォームの下限である **1時間（`3600`）** に設定するのが、コンソール運用における現実的な最短値
- どうしても 1時間未満に短縮したい場合は、コンソールでのスイッチロールを諦め、CLI 経由で `DurationSeconds` を指定する運用に倒すか、IAM Identity Center が使えるようになった際に再移行を検討する
