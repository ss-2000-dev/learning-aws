# IAM グループ管理 → スイッチロール移行ガイド

## 背景

当初 IAM Identity Center への移行を検討していたが、**組織側の事情により却下**となった。

- IAM Identity Center は AWS Organizations の**管理アカウント側で組織全体に対して有効化**する必要がある
- 現在利用している AWS アカウントは Organizations の**メンバーアカウント**であり、管理アカウントが組織全体に対して有効化しない限り、メンバーアカウント側でマルチアカウント権限や Permission Set を作成する権限を持てない
- 管理アカウントの操作権限を持たないため、この前提を満たせず断念

代替として、**IAM のクロスアカウントロール（スイッチロール）** を使ったマルチアカウント権限管理に方針転換した。スイッチロールは各メンバーアカウント側の IAM 操作だけで完結するため、Organizations 管理アカウント側の追加設定なしに導入できる。

## 前提シナリオ

- 現在: 1つの AWS アカウント（以下「ベースアカウント」）に IAM ユーザーが所属し、`DevelopersTestGroup`（AWS管理ポリシー `PowerUserAccess`）、`InfraTestGroup`（カスタムのインラインポリシー）という2つの IAM グループで権限を管理している（[../../IAMIdentityCenter/sample/before/iam-groups.yaml](../../IAMIdentityCenter/sample/before/iam-groups.yaml) と同じ構成）
- 移行後: **開発 (Dev) / 検証 (Staging) / 商用 (Production)** の3つの環境ごとに AWS アカウントを分け、ベースアカウントのユーザーがスイッチロールで各環境アカウントに切り替えてアクセスする
- 商用環境のみ、特定ユーザーに限定してアクセスを許可する

## 結論だけ知りたい場合

- **スイッチロールのセッション時間は、コンソールの「ロールの切り替え」機能を使う限り 1時間（60分）より短くはできない**。IAM Identity Center の 15分という下限とは異なる（[02-セッション時間.md](./02-セッション時間.md) 参照）
- 商用環境の限定公開は、ベースアカウント側の権限付与を絞るだけでなく、**商用アカウント側のロールの信頼ポリシー（Principal）自体を許可ユーザーだけに絞る**のが本命の対策（[04-環境別アクセス制御.md](./04-環境別アクセス制御.md) 参照）
