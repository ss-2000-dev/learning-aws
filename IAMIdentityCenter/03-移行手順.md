# 移行手順

[01-現状整理と全体方針.md](./01-現状整理と全体方針.md) の方針に基づき、グループ単位の段階移行で進める。

## フェーズ 0: 前提準備

1. AWS Organizations を有効化する（1 アカウントのみの運用でも、IAM Identity Center の有効化には Organizations が前提として必要。対象アカウントがそのまま Organizations の管理アカウントになる）
2. 管理アカウントで IAM Identity Center を有効化
   - Identity source は「Identity Center ディレクトリ」を選択（デフォルト）
3. SSO インスタンスの ARN と Identity Store ID を取得（後続の CFN テンプレートで使用）
   ```bash
   aws sso-admin list-instances
   # => InstanceArn, IdentityStoreId が取得できる
   ```
4. AWS アクセスポータルの URL（`https://xxxx.awsapps.com/start` 形式）を確認し、利用者への周知文言を準備しておく

## フェーズ 1: 現状の棚卸し

1. Excel 台帳から以下を抽出する
   - ユーザー一覧（氏名、メールアドレス、所属、現在アタッチされている IAM グループ）
   - 退職済み・休止中など、台帳と実態がずれている可能性のあるレコードを洗い出す
2. 既存 CFN の IAM グループ／ポリシースタックを確認し、グループごとにアタッチされているポリシー内容を整理する
3. 「IAM グループ → Permission Set」の対応表を作成する（1 グループ 1 Permission Set を基本とし、権限が重複しているグループがあればこのタイミングで統廃合を検討する）

## フェーズ 2: Permission Set / Group / Assignment を CFN で構築

[02-CloudFormation管理方針.md](./02-CloudFormation管理方針.md) の通り、以下を CFN で定義する（サンプルは [templates/](./templates) 参照）。

1. `AWS::IdentityStore::Group` でグループを作成（既存 IAM グループ名を踏襲）
2. `AWS::SSO::PermissionSet` で権限を定義（既存 IAM グループにアタッチされていたポリシーを移植）
   - AWS 管理ポリシーはそのまま `ManagedPolicies` に指定
   - カスタムポリシーは `CustomerManagedPolicyReferences` または `InlinePolicy` に移植
3. `AWS::SSO::Assignment` で「グループ × Permission Set × 対象アカウント」を割り当てる（対象アカウントは唯一のアカウントに固定）
   - 最初は移行対象の 1 グループのみで試験導入する

デプロイ後、Identity Center コンソールでグループと Permission Set が意図通り作成されていることを確認する。

## フェーズ 3: ユーザー作成（CFN 管理外）

ユーザー作成は CloudFormation では行わない（[02-CloudFormation管理方針.md](./02-CloudFormation管理方針.md) 参照）。

1. Excel 台帳の内容をもとに、Identity Store にユーザーを作成する
   - 少人数であればコンソールから手動作成
   - 人数が多い場合は棚卸し済みの CSV から一括投入するスクリプトを用意する（例: `aws identitystore create-user` をループ実行）
   ```bash
   aws identitystore create-user \
     --identity-store-id d-xxxxxxxxxx \
     --user-name "taro.yamada" \
     --display-name "Taro Yamada" \
     --name '{"GivenName":"Taro","FamilyName":"Yamada"}' \
     --emails '[{"Value":"taro.yamada@example.com","Type":"work","Primary":true}]'
   ```
2. 作成したユーザーを、フェーズ 2 で作成したグループに追加する
   ```bash
   aws identitystore create-group-membership \
     --identity-store-id d-xxxxxxxxxx \
     --group-id <group-id> \
     --member-id UserId=<user-id>
   ```
3. 作業後、台帳側にも「Identity Center 移行済み」のフラグを立てておく（最終的に台帳自体を廃止するまでの経過措置）

## フェーズ 4: 動作確認

1. 移行した 1 グループのユーザーに、AWS アクセスポータル URL でログインしてもらう
2. Permission Set 経由でアサインした権限が想定通りであることを確認する
   - 想定外の権限が付与されていないか（過剰権限）
   - 必要な操作が行えるか（過小権限）
3. 問題なければ次のグループへ展開する（フェーズ 2〜4 を繰り返す）

## フェーズ 5: 並行運用とモニタリング

1. 移行済みグループについても、IAM ユーザーはすぐには削除せず一定期間並行稼働させる
2. CloudTrail で該当 IAM ユーザーの `EventSource` / `userIdentity` を確認し、Identity Center 経由のアクセスに切り替わっていることを確認する
3. 一定期間（目安: 2〜4 週間）IAM ユーザー経由のアクセスが検出されなければ、そのユーザーは移行完了とみなす

## フェーズ 6: IAM ユーザーの無効化・削除

1. まず対象 IAM ユーザーのコンソールパスワード・アクセスキーを無効化する（即削除せず、切り戻せる状態を維持）
2. 一定期間問題が起きないことを確認したうえで、IAM ユーザーを削除する
3. 全ユーザーの移行が完了したグループについては、対応する IAM グループ／ポリシーの CFN スタックを削除する

## フェーズ 7: 全グループ移行完了後の後片付け

1. Excel 台帳を廃止し、Identity Center のユーザー一覧を正とする運用に切り替える（運用ルールは [04-移行後の運用ルール.md](./04-移行後の運用ルール.md) 参照）
2. 旧 IAM グループ／ポリシーの CFN テンプレートをリポジトリから削除する
3. 移行完了をチームに周知する
