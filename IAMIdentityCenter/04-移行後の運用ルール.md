# 移行後の運用ルール

移行完了後、Excel 台帳の代わりに Identity Center 自体を正として運用するためのルール。

## 入社（ユーザー追加）

1. Identity Store にユーザーを作成する（コンソール or スクリプト。CFN では行わない）
2. 所属チームに対応する既存グループにユーザーを追加する
   - 対応するグループが存在しない場合は「グループ新設」の手順（下記）を先に行う
3. 追加後、本人にアクセスポータル URL を案内する

## 退職・異動（ユーザー削除・グループ変更）

1. 退職確定次第、**即座に**該当ユーザーをすべてのグループから削除する（アクセス遮断が最優先）
2. 猶予期間後、Identity Store からユーザー自体を削除する
3. 異動の場合は、旧グループから削除し新グループに追加する（ユーザー自体は削除しない）

## 権限変更（Permission Set の変更）

1. Permission Set の中身（アタッチするポリシー等）は CFN テンプレートを変更する PR を作成する
2. レビュー・承認を経てデプロイする
3. 既存グループの権限を変更するだけであれば Assignment の変更は不要（Permission Set の中身だけ変わる）

## グループ新設・アカウント追加

1. 新しいロール／チームができた場合、CFN テンプレートに以下を追加する PR を作成する
   - `AWS::IdentityStore::Group`（グループ定義）
   - `AWS::SSO::PermissionSet`（権限定義）
   - `AWS::SSO::Assignment`（対象アカウントへの割り当て）
2. レビュー・承認を経てデプロイし、その後ユーザーをグループに追加する

## 定期棚卸し

- 四半期に一度など定期的に、Identity Store のユーザー一覧と実際の在籍者を突き合わせる棚卸しを行う
  - 従来 Excel 台帳で行っていた棚卸しを、Identity Center のユーザー一覧に対して行う形に置き換える
- Account Assignment の一覧（どのグループがどのアカウントにアクセスできるか）も合わせてレビューし、不要になった割り当てがないか確認する

## まとめ: 変更内容と管理方法の対応

| 変更内容 | 管理方法 |
|---|---|
| ユーザー作成・削除 | コンソール／スクリプト（CFN 管理外） |
| グループメンバーシップの変更 | コンソール／スクリプト（CFN 管理外。例外は [02-CloudFormation管理方針.md](./02-CloudFormation管理方針.md) 参照） |
| Permission Set の権限内容変更 | CFN（PR レビュー必須） |
| グループ新設 | CFN（PR レビュー必須） |
| アカウントへの割り当て変更 | CFN（PR レビュー必須） |
