# 移行手順（サンプルシナリオ実践編）

[README.md](./README.md) のシナリオを、実際に [../03-移行手順.md](../03-移行手順.md) のフェーズに沿ってデプロイする場合の具体例。

> 以下のアカウント ID・ARN 等はすべて説明用のダミー値。
> - Identity Store ID: `d-9067123abc`
> - SSO インスタンス ARN: `arn:aws:sso:::instance/ssoins-8a2b7c6d5e4f3210`
> - 管理対象アカウント ID: `111122223333`

## フェーズ 0: 前提準備

```bash
aws sso-admin list-instances
```

出力例:
```json
{
  "Instances": [
    {
      "InstanceArn": "arn:aws:sso:::instance/ssoins-8a2b7c6d5e4f3210",
      "IdentityStoreId": "d-9067123abc"
    }
  ]
}
```

以降、この `InstanceArn` と `IdentityStoreId` を使う。

## フェーズ 1: 現状の棚卸し

[before/iam-groups.yaml](./before/iam-groups.yaml) から、既存のグループと権限を確認する。

```bash
aws cloudformation describe-stacks --stack-name iam-groups \
  --query "Stacks[0].Outputs"
```

Excel 台帳からは以下のようなユーザー一覧が得られている想定:

| ユーザー名 | メールアドレス | 所属グループ |
|---|---|---|
| taro.yamada | taro.yamada@example.com | Developers |
| hanako.suzuki | hanako.suzuki@example.com | Infra |

「IAM グループ → Permission Set」の対応表は [README.md](./README.md#対応表) の通り。

## フェーズ 2: Group / Permission Set / Assignment を CFN でデプロイ

### 2-1. グループを作成

```bash
aws cloudformation deploy \
  --template-file after/identity-center-groups.yaml \
  --stack-name identity-center-groups \
  --parameter-overrides IdentityStoreId=d-9067123abc

aws cloudformation describe-stacks --stack-name identity-center-groups \
  --query "Stacks[0].Outputs"
# => DevelopersGroupId, InfraGroupId が取得できる
```

### 2-2. Permission Set を作成

```bash
aws cloudformation deploy \
  --template-file after/identity-center-permission-sets.yaml \
  --stack-name identity-center-permission-sets \
  --parameter-overrides SsoInstanceArn=arn:aws:sso:::instance/ssoins-8a2b7c6d5e4f3210

aws cloudformation describe-stacks --stack-name identity-center-permission-sets \
  --query "Stacks[0].Outputs"
# => DevelopersPermissionSetArn, InfraPermissionSetArn が取得できる
```

### 2-3. Assignment を作成

フェーズ 2-1, 2-2 の Outputs を Parameters に渡す。

```bash
aws cloudformation deploy \
  --template-file after/identity-center-assignments.yaml \
  --stack-name identity-center-assignments \
  --parameter-overrides \
    SsoInstanceArn=arn:aws:sso:::instance/ssoins-8a2b7c6d5e4f3210 \
    DevelopersGroupId=<2-1で取得したDevelopersGroupId> \
    DevelopersPermissionSetArn=<2-2で取得したDevelopersPermissionSetArn> \
    InfraGroupId=<2-1で取得したInfraGroupId> \
    InfraPermissionSetArn=<2-2で取得したInfraPermissionSetArn> \
    TargetAccountId=111122223333
```

デプロイ後、Identity Center コンソールで `Developers` / `Infra` グループと `DevelopersAccess` / `InfraAccess` Permission Set、およびそれぞれのアカウントへの割り当てが作成されていることを確認する。

## フェーズ 3: ユーザー作成（CFN 管理外）

Excel 台帳のユーザーを Identity Store に作成し、対応するグループに追加する。

```bash
# taro.yamada（Developers）
aws identitystore create-user \
  --identity-store-id d-9067123abc \
  --user-name "taro.yamada" \
  --display-name "Taro Yamada" \
  --name '{"GivenName":"Taro","FamilyName":"Yamada"}' \
  --emails '[{"Value":"taro.yamada@example.com","Type":"work","Primary":true}]'
# => UserId を控える

aws identitystore create-group-membership \
  --identity-store-id d-9067123abc \
  --group-id <2-1で取得したDevelopersGroupId> \
  --member-id UserId=<上記で取得したUserId>

# hanako.suzuki（Infra）
aws identitystore create-user \
  --identity-store-id d-9067123abc \
  --user-name "hanako.suzuki" \
  --display-name "Hanako Suzuki" \
  --name '{"GivenName":"Hanako","FamilyName":"Suzuki"}' \
  --emails '[{"Value":"hanako.suzuki@example.com","Type":"work","Primary":true}]'
# => UserId を控える

aws identitystore create-group-membership \
  --identity-store-id d-9067123abc \
  --group-id <2-1で取得したInfraGroupId> \
  --member-id UserId=<上記で取得したUserId>
```

## フェーズ 4: 動作確認

1. `taro.yamada` に AWS アクセスポータルでログインしてもらい、`PowerUserAccess` 相当の操作ができる／IAM や Organizations の操作ができないことを確認する（想定は Developers なので IAM 拒否は元々ない。過剰権限がないかの確認）
2. `hanako.suzuki` に同様にログインしてもらい、EC2 / ELB / ASG / CloudFormation の操作ができる、かつ IAM / Organizations の操作が拒否されることを確認する

## フェーズ 5〜7: 並行運用 → IAM ユーザー無効化・削除 → 後片付け

[../03-移行手順.md](../03-移行手順.md) のフェーズ 5〜7 と同様。

このシナリオ特有の後片付けとしては、全ユーザーの移行完了後に以下を実施する。

```bash
aws cloudformation delete-stack --stack-name iam-groups
```

[before/iam-groups.yaml](./before/iam-groups.yaml) で作成していた `Developers` / `Infra` の IAM グループとポリシーが削除される。
