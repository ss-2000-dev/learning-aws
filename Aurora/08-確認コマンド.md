# 08. テーブルや DB が意図通りにできたか確認する

構築したら「ちゃんと意図通りにできているか」を必ず確認する。ここでは確認に使うコマンドをまとめる。

---

## まず全体像を確認する（\ 系メタコマンド）

`\d`（describe）系のメタコマンドが確認の主役。**`+` をつけると詳細**（サイズ・コメントなど）が増える。

| コマンド | 確認できるもの |
|---|---|
| `\l` | データベース一覧 |
| `\dn` | スキーマ一覧 |
| `\dt` | テーブル一覧 |
| `\d テーブル名` | **テーブルの構造（カラム・型・制約・インデックス）** |
| `\d+ テーブル名` | 上記＋サイズ・コメント・ストレージ |
| `\di` | インデックス一覧 |
| `\dv` | ビュー一覧 |
| `\ds` | シーケンス（連番）一覧 |
| `\df` | 関数一覧 |
| `\du` | ロール（ユーザー）一覧 |
| `\dp` / `\z` | テーブルの権限一覧 |

---

## テーブルの構造を確認する（一番よく使う）

```
appdb=> \d users
```
```
                                     Table "public.users"
   Column   |           Type           | Nullable |             Default
------------+--------------------------+----------+----------------------------------
 id         | bigint                   | not null | nextval('users_id_seq'::regclass)
 email      | text                     | not null |
 status     | text                     | not null | 'active'::text
 created_at | timestamp with time zone | not null | now()
Indexes:
    "users_pkey" PRIMARY KEY, btree (id)
    "users_email_key" UNIQUE CONSTRAINT, btree (email)
    "idx_users_status" btree (status)
Foreign-key constraints:
    "users_team_id_fkey" FOREIGN KEY (team_id) REFERENCES teams(id)
Referenced by:
    TABLE "orders" CONSTRAINT "orders_user_id_fkey" FOREIGN KEY (user_id) REFERENCES users(id)
```

**チェックすべきポイント**：

| 見る場所 | 確認すること |
|---|---|
| Column / Type | カラム名・型は意図通りか（例: 金額が integer か numeric か） |
| Nullable | `not null` にすべき列がなっているか |
| Default | デフォルト値（`now()` や連番）は正しいか |
| Indexes | 主キー・ユニーク・必要なインデックスがあるか |
| Foreign-key constraints | 外部キーが張られているか |
| Referenced by | この表がどこから参照されているか |

## 意図通りか確認する具体的なチェック集

### データ件数を確認

```sql
SELECT count(*) FROM users;                    -- 総件数
SELECT status, count(*) FROM users GROUP BY status;  -- 区分ごとの件数
```

### 中身をちょっと見る

```sql
SELECT * FROM users LIMIT 5;             -- 先頭5件
SELECT * FROM users ORDER BY id DESC LIMIT 5;  -- 最新5件
TABLE users;                             -- SELECT * FROM users; の短縮形
```

> 💡 横に長くて見づらい時は **`\x`** で縦型表示に切り替えると読みやすい（[10参照](./10-便利なコマンド集.md)）。

### 制約（NOT NULL / UNIQUE / CHECK / 外部キー）を確認

```sql
-- テーブルの全制約を一覧
SELECT conname, contype, pg_get_constraintdef(oid)
FROM pg_constraint
WHERE conrelid = 'users'::regclass;
--  contype: p=主キー, u=ユニーク, f=外部キー, c=CHECK, n=NOT NULL
```

### カラムの詳細を information_schema で確認

```sql
SELECT column_name, data_type, is_nullable, column_default
FROM information_schema.columns
WHERE table_name = 'users'
ORDER BY ordinal_position;
```

### テーブルのサイズを確認

```sql
-- テーブル＋インデックス込みのサイズ
SELECT pg_size_pretty(pg_total_relation_size('users'));

-- DB内の全テーブルをサイズ順に
SELECT relname, pg_size_pretty(pg_total_relation_size(relid)) AS size
FROM pg_stat_user_tables
ORDER BY pg_total_relation_size(relid) DESC;
```

### シーケンス（連番）が意図通り進んでいるか

```sql
-- 次に採番される値を確認
SELECT last_value FROM users_id_seq;
```

## 「作ったはずのものが無い / 見えない」時のチェック

初心者がハマりやすいポイント。

### ① 別の DB / スキーマにいる

```sql
SELECT current_database();   -- 今どのDBにいる？
SELECT current_schema();     -- 今どのスキーマ？
\dn                          -- スキーマ一覧
```
`\c 正しいDB名` で DB を切り替える。テーブルが別スキーマにあるなら `\dt 別スキーマ名.*`。

### ② 検索パス（search_path）がずれている

`public` 以外のスキーマにテーブルを作ると、`\dt` で見えないことがある。

```sql
SHOW search_path;               -- 今の検索パス
SET search_path TO myschema, public;  -- 一時的に変更
\dt myschema.*                  -- スキーマを明示して一覧
```

### ③ 権限がなくて見えない

```sql
-- 全スキーマのテーブルを強制的に見る
SELECT schemaname, tablename FROM pg_tables ORDER BY 1, 2;
```

---

## 構築後の最終確認チェックリスト（商用）

```
□ \l         で目的の DB が存在し、ENCODING が UTF8 か
□ \dt        で必要なテーブルが全部あるか
□ \d テーブル で 型・NOT NULL・デフォルト・主キーが意図通りか
□ \di        で必要なインデックスがあるか（特に外部キー列）
□ \dp        で権限が最小権限になっているか（アプリユーザーに過剰な権限がないか）
□ \du        でユーザー・ロールの構成が正しいか
□ \d+        でコメントがついているか
□ SELECT count(*) で初期データ件数が想定通りか
□ 外部キー・UNIQUE 制約が効くか（わざと重複INSERTしてエラーになるか BEGIN;〜ROLLBACK; で試す）
```
