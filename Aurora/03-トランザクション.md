# 03. トランザクション（commit / rollback / 自動コミット）

## トランザクションとは（超重要な概念）

**トランザクション**とは、「複数の操作を**まとめて1つの塊**として扱い、**全部成功したら反映／途中で失敗したら全部無かったことにする**」仕組み。

たとえば「A口座から1万円引いて、B口座に1万円足す」を考えると、
- ✅ 両方成功 → 反映する（COMMIT）
- ❌ 片方だけ成功して片方失敗 → **1万円が消える**。だから両方無かったことにする（ROLLBACK）

この「全部やるか、全部やらないか（All or Nothing）」を保証するのがトランザクション。

---

## COMMIT と ROLLBACK

| コマンド | 意味 | イメージ |
|---|---|---|
| `BEGIN;` | トランザクション開始 | 「お試しモード」に入る |
| `COMMIT;` | 変更を**確定**して保存する | 「これで確定！」保存ボタン |
| `ROLLBACK;` | 変更を**破棄**して元に戻す | 「無かったことに」Undo |

### 基本の流れ

```sql
BEGIN;                                    -- ① 開始
UPDATE accounts SET balance = balance - 10000 WHERE id = 1;  -- A口座
UPDATE accounts SET balance = balance + 10000 WHERE id = 2;  -- B口座
SELECT * FROM accounts WHERE id IN (1, 2);  -- ② 結果を目で確認
COMMIT;                                   -- ③ OKなら確定
-- もし②で「あれ、おかしい」と思ったら COMMIT せず ROLLBACK; を打つ
```

### 商用での鉄板：危険な操作は BEGIN で囲んで確認してから COMMIT

初心者が本番で `UPDATE` / `DELETE` するときの**事故防止テクニック**。

```sql
BEGIN;

-- まず「何件消えるのか」を SELECT で確認（WHERE を必ずつける）
SELECT count(*) FROM users WHERE status = 'inactive';   -- 例: 3件

-- 同じ条件で削除
DELETE FROM users WHERE status = 'inactive';
-- → "DELETE 3" と出る。SELECTの件数と一致すればOK

-- 一致しない・不安なら
ROLLBACK;    -- 無かったことに

-- 件数が想定通りなら
COMMIT;      -- 確定
```

> ⚠️ `WHERE` を付け忘れた `DELETE FROM users;` は**全件削除**。`BEGIN;` してあれば `ROLLBACK;` で助かる。だから危険な操作の前は必ず `BEGIN;`。

## 自動コミット（AUTOCOMMIT）とは

psql は**デフォルトで「自動コミット ON」**になっている。つまり `BEGIN;` を打たずに実行した SQL は、**1文ごとに即座に COMMIT される**（＝すぐ確定して、後から ROLLBACK できない）。

```sql
-- 自動コミットON（デフォルト）の場合
DELETE FROM users WHERE id = 5;   -- この瞬間に確定してしまう。取り消せない！
```

`BEGIN;` を打つと、その時だけ自動コミットが一時停止し、`COMMIT;` するまで確定しない。

### 今コミットされたか（自動コミットの状態）を確認する

psql の設定変数を `\echo` で確認できる。

```
\echo :AUTOCOMMIT
```

- `on` … 自動コミット ON（1文ごとに即確定。デフォルト）
- `off` … 自動コミット OFF（自分で COMMIT するまで確定しない）

> 💡 質問にあった「echo でコミットしているか確認」は、この **`\echo :AUTOCOMMIT`** のこと。`:AUTOCOMMIT` は psql の内部変数で、コロン `:` をつけると中身が展開される。

### 自動コミットを OFF にする（慎重に作業したい時）

```
\set AUTOCOMMIT off
```

OFF にすると、最初の SQL を打った時点で自動的にトランザクションが始まり、**自分で `COMMIT;` するまで一切確定しない**。本番で慎重に作業したい時に有効。

```
\set AUTOCOMMIT off      -- OFFにする
DELETE FROM users WHERE id = 5;
-- まだ確定していない。COMMIT; するまで他の人からは消えて見えない
COMMIT;                  -- ここで確定
\set AUTOCOMMIT on       -- 元に戻す
```

> ⚠️ AUTOCOMMIT OFF のまま `\q` で終了すると、未 COMMIT の変更は **ROLLBACK（破棄）** される。「保存したはずなのに消えた」はこれが原因のことが多い。

## 今トランザクションの中にいるか確認する

「今 BEGIN した状態なんだっけ？」を確認する方法。

### 方法1：プロンプトを見る（一番早い）

トランザクション中はプロンプトに **`*`** がつく。

```
appdb=>      ← 通常（トランザクション外）
appdb=*>     ← トランザクションの中（BEGIN した後、COMMIT前）
appdb=!>     ← トランザクションが失敗状態（エラー後。ROLLBACKが必要）
```

詳しくは [04-プロンプトの記号の意味.md](./04-プロンプトの記号の意味.md)。

### 方法2：現在の状態を関数で確認

```sql
-- トランザクションIDが割り当てられているか等で判断する上級者向け
SELECT now();  -- トランザクション中は、BEGINした時刻で固定される
```

## トランザクションがエラーになった時（失敗状態）

トランザクション中に SQL がエラーになると、以降のコマンドが全部こう言われる：

```
ERROR:  current transaction is aborted, commands ignored until end of transaction block
```

これは「**このトランザクションはもう失敗している。ROLLBACK するまで何も受け付けない**」という状態。プロンプトは `appdb=!>` になる。対処：

```sql
ROLLBACK;   -- いったん全部戻して、やり直す
```

### 一部だけやり直したい：SAVEPOINT

長いトランザクションで「ここまでは残したい」時は、途中に**セーブポイント（中間保存地点）**を打てる。

```sql
BEGIN;
INSERT INTO users VALUES (...);   -- これは残したい
SAVEPOINT sp1;                    -- セーブポイント
INSERT INTO orders VALUES (...);  -- これがもし失敗したら
ROLLBACK TO sp1;                  -- sp1 まで戻す（usersのINSERTは残る）
COMMIT;
```

## まとめ：本番で DELETE / UPDATE する時の安全手順

```sql
-- 1. トランザクション開始
BEGIN;

-- 2. 対象を SELECT で確認（消す前に何件か見る）
SELECT count(*) FROM 対象テーブル WHERE 条件;

-- 3. 実行（WHERE を SELECT と完全に同じにする）
DELETE FROM 対象テーブル WHERE 条件;

-- 4. 実行件数が 2 の件数と一致するか確認

-- 5a. OK なら確定
COMMIT;
-- 5b. おかしければ破棄
ROLLBACK;
```
