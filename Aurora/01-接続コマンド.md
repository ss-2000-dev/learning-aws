# 01. ターミナルから Aurora (PostgreSQL) へ接続する

## 前提：接続に必要な5つの情報

Aurora に接続するには、以下の情報が必要。AWS のマネジメントコンソールや、インフラ担当者から入手する。

| 項目 | 説明 | 例 |
|---|---|---|
| **ホスト（エンドポイント）** | Aurora の接続先アドレス | `mydb.cluster-xxxx.ap-northeast-1.rds.amazonaws.com` |
| **ポート** | PostgreSQL は通常 5432 | `5432` |
| **DB名** | 接続するデータベース名 | `appdb` |
| **ユーザー名** | ログインするユーザー（ロール） | `app_user` |
| **パスワード** | そのユーザーのパスワード | `********` |

> 💡 **エンドポイントには2種類ある**
> - **クラスターエンドポイント（Writer）** … 読み書き両方できる。`cluster-` が含まれる。DB構築や更新はこちら。
> - **リーダーエンドポイント（Reader）** … 読み取り専用。`cluster-ro-` が含まれる。参照だけの負荷分散用。
>
> DB を作る・変更する作業では**必ず Writer（クラスターエンドポイント）**に接続すること。

## 接続方法いろいろ

### 方法1：オプションを個別に指定する（基本形）

```bash
psql -h <エンドポイント> -p 5432 -U <ユーザー名> -d <DB名>
```

| オプション | 意味 | 覚え方 |
|---|---|---|
| `-h` | host（ホスト＝接続先） | **h**ost |
| `-p` | port（ポート番号） | **p**ort |
| `-U` | User（ユーザー名）※大文字 | **U**ser |
| `-d` | database（DB名） | **d**atabase |

実行するとパスワードを聞かれるので入力する（画面には表示されない）。

```bash
psql -h mydb.cluster-xxxx.ap-northeast-1.rds.amazonaws.com -p 5432 -U app_user -d appdb
# Password for user app_user: ← ここで入力
```

### 方法2：接続文字列（キー=値）でまとめて指定 ★おすすめ

Aurora は **SSL 接続を推奨**しているので、`sslmode=require` をつけられるこの書き方が安全でおすすめ。

```bash
psql "host=mydb.cluster-xxxx.ap-northeast-1.rds.amazonaws.com port=5432 dbname=appdb user=app_user sslmode=require"
```

### 方法3：URL 形式（postgresql://）

アプリの接続設定と同じ形式。1行でコピペしやすい。

```bash
psql "postgresql://app_user:パスワード@mydb.cluster-xxxx.ap-northeast-1.rds.amazonaws.com:5432/appdb?sslmode=require"
```

> ⚠️ パスワードを URL に直接書くと、シェルの履歴（`history`）に残る。避けたい場合は方法2 か、後述の環境変数 / `.pgpass` を使う。

## パスワードを毎回入力しない方法

### 方法A：環境変数で渡す（一時的）

```bash
# その場かぎり（1コマンドだけ有効）
PGPASSWORD='パスワード' psql -h <エンドポイント> -U app_user -d appdb
```

### 方法B：`.pgpass` ファイルに保存する（おすすめ・恒久的）

ホームディレクトリに `~/.pgpass` を作ると、psql が自動で読んでくれる。

```bash
# 書式: ホスト:ポート:DB名:ユーザー名:パスワード
echo "mydb.cluster-xxxx.ap-northeast-1.rds.amazonaws.com:5432:appdb:app_user:パスワード" >> ~/.pgpass

# 必ず本人だけ読める権限にする（これをしないと psql が無視する）
chmod 600 ~/.pgpass
```

以降はパスワード入力なしで接続できる。`*`（ワイルドカード）も使える：

```
# 全DB・全ユーザーで同じパスワードなら
mydb.cluster-xxxx.ap-northeast-1.rds.amazonaws.com:5432:*:*:パスワード
```

> 💡 `chmod 600` を忘れると「WARNING: password file has group or world access」と出て無視される。必ず設定する。

## Aurora ならではの接続の注意点

### ネットワーク（ここでつまづく人が多い）

Aurora は通常 **VPC の中（プライベート）** にあるため、自分の PC から直接は繋がらないことが多い。以下のいずれかが必要：

| 経路 | 説明 |
|---|---|
| **踏み台サーバー（Bastion）経由** | VPC 内の EC2 に SSH で入り、そこから psql |
| **SSH ポートフォワード（トンネル）** | 手元の PC から踏み台経由でトンネルを掘る（下記） |
| **VPN / Direct Connect** | 社内ネットワークが VPC と繋がっている場合 |

**SSH トンネルの例**（踏み台 EC2 経由で、手元の 5432 を Aurora に転送）：

```bash
# 手元PCの localhost:5432 → 踏み台 → Aurora:5432 へトンネル
ssh -N -L 5432:mydb.cluster-xxxx.ap-northeast-1.rds.amazonaws.com:5432 ec2-user@踏み台のIP

# 別のターミナルで、localhost に対して psql すると Aurora に繋がる
psql "host=localhost port=5432 dbname=appdb user=app_user sslmode=require"
```

### セキュリティグループ

接続元（PCや踏み台）の IP / セキュリティグループから、Aurora のセキュリティグループの **5432 ポートへのインバウンド許可**が必要。繋がらないときはまずここを疑う。

## 接続できたか確認する

接続に成功すると、プロンプトが以下のように変わる：

```
appdb=>
```

`appdb` が接続中の DB 名。今どこに繋がっているか不安になったら：

```
\conninfo
```

```
You are connected to database "appdb" as user "app_user" on host "..." at port "5432".
```

> プロンプトの `=>` や `=#` などの記号の意味は [04-プロンプトの記号の意味.md](./04-プロンプトの記号の意味.md) を参照。

---

## 接続を終了する

```
\q
```

（`\q` は quit の q。SSH トンネルを張っている場合は、そちらの ssh も Ctrl+C で止める）

---

## よくあるエラーと対処

| エラー | 原因 | 対処 |
|---|---|---|
| `could not connect to server: Connection timed out` | ネットワーク未到達（SG / VPC） | セキュリティグループの 5432 許可、踏み台経由を確認 |
| `password authentication failed for user "xxx"` | ユーザー名かパスワードが違う | 認証情報を再確認 |
| `FATAL: database "xxx" does not exist` | DB名が違う | `\l` で存在する DB 名を確認（まず `postgres` DB に繋ぐ） |
| `no pg_hba.conf entry ... no encryption` | SSL 必須なのに平文接続 | `sslmode=require` をつける |
| `psql: command not found` | psql が入っていない | `brew install libpq` （Mac）等で PostgreSQL クライアントを入れる |

> 💡 **とりあえず繋ぎたい**とき：接続先の DB 名が分からなければ、PostgreSQL には最初から存在する `postgres` という管理用 DB に繋ぐとよい（`dbname=postgres`）。繋いでから `\l` で DB 一覧を見て、目的の DB に `\c appdb` で切り替える。
