# 04. ターミナルのプロンプトに「*」や「'」がつく理由

psql のプロンプト（`appdb=>` の部分）は、**今の状態を記号で教えてくれている**。
初心者が「あれ、Enter しても何も起きない」「変な記号が出て打てない」となる原因の多くはこれ。読み方を知れば怖くない。

---

## プロンプトの基本構造

```
appdb=>
 └┬─┘└┬┘
  │   └─ 状態を表す記号（ここが変化する）
  └───── 接続中のデータベース名
```

---

## 1文字目：接続ユーザーの種類

| プロンプト | 意味 |
|---|---|
| `appdb=>` | 通常ユーザーで接続中（`>`） |
| `appdb=#` | スーパーユーザー / rds_superuser で接続中（`#`） |

> `#` は「管理者権限で繋いでいる」サイン。Aurora のマスターユーザーだと `#` になる。**強い権限なので操作は慎重に**、という目印。

---

## 「-」が出る：SQL がまだ終わっていない（セミコロン待ち）

これが**一番多い「あれ？打てない」の原因**。

```
appdb=> SELECT * FROM users     ← ; を付け忘れて Enter した
appdb->                          ← 「まだ続きを待ってるよ」の意味
```

`=` が **`-`** に変わったら、「**SQL 文がまだ完成していない（セミコロン `;` がない）**」というサイン。psql は `;` が来るまで、1つの SQL 文だと思って待ち続ける。

**対処**：`;` を打って Enter すれば実行される。

```
appdb-> ;      ← セミコロンを打つと実行される
```

複数行にわたる SQL では正常な挙動。わざと改行して書ける：

```
appdb=> SELECT id, name
appdb->   FROM users
appdb->  WHERE id = 1;      ← ここで ; を打って完成・実行
```

---

## 「*」が出る：トランザクションの中にいる

```
appdb=*>
    ↑ ここに * がつく
```

**`*`（アスタリスク）は「今トランザクションの中にいる」**サイン。`BEGIN;` を打つと出て、`COMMIT;` か `ROLLBACK;` を打つと消える。

```
appdb=>  BEGIN;        ← トランザクション開始
appdb=*> ...           ← * がついた（トランザクション中）
appdb=*> COMMIT;       ← 確定
appdb=>                ← * が消えた（通常に戻った）
```

> 💡 `*` が出ている間は**まだ変更が確定していない**。`COMMIT;` を忘れて放置したり `\q` すると、変更が破棄されることがある。「あれ？保存したのに消えた」の原因はこれ。

---

## 「!」が出る：トランザクションが失敗状態

```
appdb=!>
    ↑ ! は「このトランザクションは失敗した」
```

トランザクション中に SQL がエラーになると、`*` が **`!`** に変わる。この状態では以降のコマンドが全部拒否される：

```
ERROR: current transaction is aborted, commands ignored until end of transaction block
```

**対処**：`ROLLBACK;` を打てば通常状態に戻る。（詳細は [03-トランザクション.md](./03-トランザクション.md)）

---

## 「'」が出る：クオート（引用符）が閉じていない

質問にあった **`'`（シングルクオート）がついてしまう**現象。

```
appdb=> INSERT INTO users (name) VALUES ('太郎);    ← ' を閉じ忘れた！
appdb'>                                              ← ' 待ちの状態
    ↑ プロンプトが ' に変わる
```

これは「**文字列を囲むシングルクオート `'` が開きっぱなしで、閉じる `'` を待っている**」状態。psql は「まだ文字列の途中だな」と思って、次の `'` が来るまで待ち続ける。

**対処**：閉じる `'` を打って文を完成させる。

```
appdb'> ');       ← ' で閉じて ) と ; で完成
```

**どうしても抜けられない・ぐちゃぐちゃになった時**：`Ctrl + C` で入力を破棄して、プロンプトを最初からやり直せる。

```
appdb'>  ^C       ← Ctrl+C で中断、appdb=> に戻る
```

---

## 「"」が出る：ダブルクオートが閉じていない

`'` の親戚。PostgreSQL では **ダブルクオート `"` は「テーブル名・カラム名（識別子）」を囲む**のに使う。これを閉じ忘れると：

```
appdb=> SELECT * FROM "user     ← " を閉じ忘れ
appdb">                          ← " 待ち
```

**対処**：`"` で閉じる。

> 💡 覚え方：**`'`（シングル）＝文字列データ**、**`"`（ダブル）＝テーブル/カラム名**。用途が違う。文字列を `"` で囲むとエラーになるので注意。

---

## 「(」が出る：カッコが閉じていない

```
appdb=> SELECT * FROM users WHERE id IN (1, 2, 3    ← ) を閉じ忘れ
appdb(>                                              ← ) 待ち
```

`(` を開いて `)` で閉じていないと、プロンプトが `(` になる。**対処**：`)` を打つ。

---

## 記号 早見表

| プロンプト末尾 | 状態 | 対処 |
|---|---|---|
| `=>` | 通常（一般ユーザー）。入力待ち | そのまま入力 |
| `=#` | 通常（スーパーユーザー） | 権限強いので慎重に |
| `->` | SQL が未完了（`;` がない） | `;` を打つ |
| `=*>` | トランザクションの中 | `COMMIT;` か `ROLLBACK;` |
| `=!>` | トランザクション失敗状態 | `ROLLBACK;` |
| `'>` | 文字列の `'` が閉じてない | `'` を打つ / `Ctrl+C` |
| `">` | 識別子の `"` が閉じてない | `"` を打つ / `Ctrl+C` |
| `(>` | カッコ `)` が閉じてない | `)` を打つ / `Ctrl+C` |
| `$>` | ドル引用符（関数定義など）が閉じてない | `$$` を打つ / `Ctrl+C` |

> 🆘 **どの記号でも、詰まったら `Ctrl + C`**。入力中のコマンドを破棄して、きれいな `appdb=>` に戻れる。これさえ覚えておけば怖くない。

---

## 補足：プロンプトの記号は組み合わさる

実際には複数が同時に出る。落ち着いて1文字ずつ読めばよい。

```
appdb=*>    通常ユーザー + トランザクション中
appdb-*#    スーパーユーザー + トランザクション中 + SQL未完了
appdb'#     スーパーユーザー + 文字列クオート待ち
```
