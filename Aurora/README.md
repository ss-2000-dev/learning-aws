## そもそも Aurora / PostgreSQL / psql とは

### 3つの言葉の関係

```
┌─────────────────────────────────────────────┐
│ Aurora（AWSのマネージドDBサービス）            │
│  ┌───────────────────────────────────────┐  │
│  │ PostgreSQL（DBの種類・エンジン）          │  │
│  │  ┌─────────────────────────────────┐  │  │
│  │  │ あなたのデータベース (例: appdb)   │  │  │
│  │  │   └ テーブル、ロール、データ...     │  │  │
│  │  └─────────────────────────────────┘  │  │
│  └───────────────────────────────────────┘  │
└─────────────────────────────────────────────┘
         ▲
         │ psql（ターミナルから接続する道具・クライアント）
         │
   [あなたのPC / 踏み台サーバー]
```

- **Aurora** … AWS が提供するマネージドなデータベースサービス。バックアップや冗長化を AWS が面倒みてくれる。
- **PostgreSQL** … データベースの種類（エンジン）のひとつ。Aurora は「PostgreSQL 互換」と「MySQL 互換」があり、今回は PostgreSQL 版。
- **psql** … PostgreSQL に**ターミナルから接続して操作するためのコマンドラインツール**。このガイドの主役。

> 💡 「Aurora のコマンド」というものは基本的に無く、**接続してしまえば普通の PostgreSQL の操作**になる。だから PostgreSQL / psql の知識がそのまま使える。

### psql の中には2種類のコマンドがある

psql に接続すると、打つコマンドは大きく2種類に分かれる。これを混同すると混乱するので最初に押さえる。

| 種類 | 例 | 特徴 |
|---|---|---|
| **SQL コマンド** | `SELECT * FROM users;` `CREATE TABLE ...;` | 標準の SQL。**末尾に `;`（セミコロン）が必要**。大文字小文字は問わない |
| **メタコマンド（psql独自）** | `\dt` `\l` `\du` `\q` | バックスラッシュ `\` で始まる psql 専用の便利コマンド。`;` は不要 |

```sql
-- SQL コマンド（; が必要）
SELECT count(*) FROM users;

-- メタコマンド（\ で始まる、; は不要）
\dt        -- テーブル一覧
\q         -- psql を終了
```

## 商用環境で事故らないための最重要ルール

初心者が商用でやりがちな事故を防ぐ、**これだけは守ってほしい**ルール。

### ① いきなり本番でやらない・まず確認する

- 可能なら **staging（検証環境）で全く同じ手順を試してから**本番へ。
- 消す・変える系の操作は、まず `SELECT` で「対象が何件あるか」を確認してから実行する。

### ② 危険な操作は「トランザクション」で囲んでやり直せるようにする

`BEGIN;` してから作業すると、間違えても `ROLLBACK;` で無かったことにできる。
（詳細は [03-トランザクション.md](./03-トランザクション.md)）

```sql
BEGIN;                          -- ここから「お試しモード」開始
UPDATE users SET status = 'x';  -- やらかしても大丈夫
SELECT count(*) FROM users WHERE status = 'x';  -- 結果を確認
-- OKなら COMMIT; / ダメなら ROLLBACK;
ROLLBACK;                       -- 無かったことにする
```

### ③ SQL ファイルを流すときは「エラーで止める」設定をつける

デフォルトだと、途中の SQL がエラーになっても**残りを実行し続けてしまう**。
`ON_ERROR_STOP=1` をつけると、最初のエラーで止まる。（詳細は [05](./05-SQLファイルの実行と初期データ投入.md)）

```bash
psql -v ON_ERROR_STOP=1 -f schema.sql
```

### ④ 本番の大きなテーブルにインデックスを貼るときは CONCURRENTLY

普通の `CREATE INDEX` はテーブルをロック（書き込み停止）してしまう。
本番では `CREATE INDEX CONCURRENTLY` を使う。（詳細は [06](./06-インデックス.md)）

### ⑤ アプリ用ユーザーには必要最小限の権限だけ渡す（最小権限の原則）

マスターユーザー（管理者）でアプリを動かさない。アプリ専用ユーザーを作り、必要な権限だけ付与する。（詳細は [02](./02-DB-ロール-ユーザー-権限.md)）

### ⑥ 変更の前にバックアップ / スナップショットを取る

大きな変更の前は、Aurora のマネジメントコンソールから**手動スナップショット**を取っておくと安心。

## まず覚える最小セット（チートシート）

これだけ知っていれば作業を始められる、という最小限。

```bash
# 接続する
psql "host=<エンドポイント> port=5432 dbname=<DB名> user=<ユーザー名> sslmode=require"
```

```
\l              -- データベース一覧
\c dbname       -- 別のDBに接続を切り替える
\dt             -- テーブル一覧
\d テーブル名    -- テーブルの構造（カラム）を表示
\du             -- ロール・ユーザー一覧
\dn             -- スキーマ一覧
\di             -- インデックス一覧
\x              -- 表示を縦型に切り替え（横に長い結果を見やすく）
\timing         -- 実行時間を表示する ON/OFF
\conninfo       -- 今どこに接続しているか確認
\?              -- メタコマンドのヘルプ
\h CREATE TABLE -- SQLコマンドの構文ヘルプ
\q              -- 終了
```
